01Parte A · Base da linguagem

Comece por aqui

Como este caderno funciona, o mapa das referências oficiais e por que juntar Python e Rust.

Referências: The Rust Programming Language · The Rust Reference · Guia do PyO3

Resumo em 30 segundos
  • Python continua sendo a linguagem da pesquisa, do notebook e da orquestração. Rust entra no caminho quente: o trecho que roda milhões de vezes, que precisa de latência previsível ou que vai rodar num microcontrolador.
  • A ponte mais usada é o PyO3 com o maturin: você escreve uma função em Rust e faz import dela no Python como se fosse um módulo comum.
  • Cada capítulo tem a mesma estrutura: o que é, para que serve, siglas, exemplos Python ↔ Rust, diagrama quando o fluxo não é óbvio e um quiz. Marque "Já estudei" para acompanhar o progresso no índice.

O que é

Rust é uma linguagem compilada, com tipagem estática e sem coletor de lixo. A memória é gerenciada por regras de ownership checadas na compilação, então o binário final não tem pausas de GC e não tem a classe de bugs de memória comum em C e C++.

Para que serve

escrever código rápido e seguro onde Python sofre: laços numéricos pesados, serviços com muitas conexões, parsers, ferramentas de linha de comando e firmware. Junto com Python, serve para acelerar só a parte crítica sem reescrever o sistema inteiro.
Siglas e termos difíceis
GC
Garbage Collector, coletor de lixo. Libera memória em tempo de execução. Python usa contagem de referências mais um coletor de ciclos; Rust não tem nenhum dos dois.
GIL
Global Interpreter Lock. Trava do CPython que deixa só uma thread executar bytecode Python por vez.
FFI
Foreign Function Interface. Mecanismo para uma linguagem chamar funções de outra.
ABI
Application Binary Interface. O "contrato binário" de como funções são chamadas na máquina (registradores, pilha, nomes).
Caminho quente
hot path, o trecho do programa onde a maior parte do tempo é gasta.
Crate
unidade de compilação do Rust: uma biblioteca ou um executável. Equivale a um pacote.

Como estudar com este caderno

  1. Leia o resumo e os cartões "O que é" e "Para que serve".
  2. Nos exemplos, alterne as abas Python e Rust. A aba que você escolher fica lembrada em todo o caderno.
  3. Rode os exemplos de Rust com cargo run e os de Python com python arquivo.py. Os exemplos com PyO3 usam maturin develop.
  4. Faça o quiz no fim do capítulo. Ele cobre o que mais cai em entrevista e em revisão de código: o que compila, o que não compila e por quê.

02Parte A · Base da linguagem

Toolchain, Cargo e maturin

As ferramentas que substituem pip, venv e setup.py, e como um projeto misto Python + Rust se organiza.

Referências: The Cargo Book · Guia do maturin · CLI Book: empacotamento

Resumo em 30 segundos
  • rustup instala e atualiza o compilador; cargo cria, compila, testa e baixa dependências; maturin empacota um crate Rust como pacote Python (wheel).
  • O projeto misto tem dois manifestos: Cargo.toml (lado Rust) e pyproject.toml (lado Python). O maturin lê os dois.
  • Use cargo check enquanto escreve, cargo clippy antes de commitar e --release sempre que for medir desempenho.

O que é

o conjunto de ferramentas oficiais. rustup gerencia versões do compilador (stable, beta, nightly). cargo é o gerenciador de projetos e pacotes. O maturin é a ferramenta da comunidade PyO3 que compila o crate e gera o pacote Python.

Para que serve

padronizar o ciclo de vida do projeto. Qualquer pessoa clona o repositório e roda cargo build ou maturin develop, sem script próprio de instalação. No Python, pip install . funciona porque o pyproject.toml aponta o maturin como backend de build.
Siglas e termos difíceis
TOML
Tom's Obvious, Minimal Language. Formato dos arquivos Cargo.toml e pyproject.toml.
Wheel
pacote Python pré-compilado (.whl). É o que o pip instala sem precisar de compilador.
abi3
ABI estável do CPython. Um wheel abi3 compilado para Python 3.9 funciona em 3.10, 3.11, 3.12 e seguintes.
cdylib
tipo de crate que gera uma biblioteca dinâmica (.so, .pyd, .dylib) para outra linguagem carregar.
Profile
perfil de compilação. dev compila rápido com checagens; release otimiza.
LTO
Link Time Optimization. Otimiza o programa inteiro no momento da ligação, entre crates.
SemVer
versionamento semântico MAIOR.MENOR.CORREÇÃO. "0.23" no Cargo aceita 0.23.x.

03Parte A · Base da linguagem

Tipos, variáveis e funções

Imutável por padrão, tipos explícitos nas fronteiras e expressões no lugar de instruções.

Referências: Reference: tipos · Book: conceitos comuns

Resumo em 30 segundos
  • let cria variável imutável; let mut permite alterar. Em Python tudo pode ser reatribuído.
  • Inteiros têm tamanho fixo (i32, u64...). Não existe o int infinito do Python, então overflow é uma preocupação real.
  • Funções declaram o tipo de cada parâmetro e do retorno. A última expressão sem ; é o valor devolvido.

O que é

o sistema de tipos estático do Rust. Cada valor tem um tipo conhecido na compilação: escalares (i64, f64, bool, char) e compostos (tupla, array). O compilador infere a maior parte, mas as assinaturas de função são sempre explícitas.

Para que serve

pegar erros antes de rodar (somar texto com número, esquecer um caso) e permitir que o compilador gere código de máquina sem checagens em tempo de execução. É o que o mypy tenta fazer no Python, só que obrigatório e com garantia.
Siglas e termos difíceis
i32, u64
inteiro com sinal de 32 bits, inteiro sem sinal de 64 bits. O número é a largura em bits.
usize
inteiro sem sinal do tamanho da palavra da CPU (64 bits no seu PC). É o tipo dos índices.
f64
ponto flutuante de 64 bits, padrão IEEE 754. É o float do Python.
IEEE 754
padrão de ponto flutuante. Explica por que 0.1 + 0.2 dá 0.30000000000000004 nas duas linguagens.
Shadowing
declarar de novo uma variável com o mesmo nome, podendo mudar o tipo.
Expressão
trecho que produz valor. Em Rust, if, match e blocos {} são expressões.

Você comprou cripto em várias datas e quer o preço médio ponderado pela quantidade. DCA é a estratégia de comprar valores fixos em intervalos regulares.

O Python levantaria ZeroDivisionError com a lista vazia. Em Rust, Option<f64> obriga quem chama a tratar o caso. Os separadores _ nos números funcionam nas duas linguagens.

04Parte A · Base da linguagem

Ownership e borrowing

A ideia central do Rust, explicada a partir de como o Python compartilha objetos.

Referências: Book: ownership · Nomicon: ownership e lifetimes · Reference: destrutores

Resumo em 30 segundos
  • Em Python, b = a faz duas variáveis apontarem para o mesmo objeto. Mudar por b muda o que a enxerga. Isso causa bugs de aliasing.
  • Em Rust, cada valor tem um dono. let b = a; move o valor: a deixa de valer. Para usar sem tomar posse, você empresta com & (leitura) ou &mut (escrita).
  • Regra de ouro: muitas referências &T ou uma única &mut T, nunca as duas ao mesmo tempo.

O que é

ownership (posse) é o conjunto de regras que define quem é responsável por liberar cada valor. borrowing (empréstimo) é usar o valor por meio de uma referência sem tomar a posse. O borrow-checker verifica tudo isso na compilação.

Para que serve

liberar memória sem coletor de lixo e eliminar, antes de rodar, bugs de ponteiro solto, liberação dupla e alteração simultânea por duas partes do código. As mesmas regras impedem corridas de dados entre threads.
Siglas e termos difíceis
Move
transferência de posse. A variável antiga fica inválida.
Copy
tipos pequenos da stack (i64, f64, bool) são copiados em vez de movidos.
Clone
cópia profunda explícita, inclusive dos dados na heap. Tem custo.
Stack / heap
pilha (rápida, tamanho fixo) e monte (tamanho dinâmico, acessado por ponteiro).
Aliasing
duas variáveis apontando para o mesmo dado.
Drop
liberação automática quando o dono sai de escopo. Base do padrão RAII.
Refcount
contagem de referências. É como o CPython sabe quando liberar um objeto.

05Parte A · Base da linguagem

Structs, enums e match

Modelar ordens de compra e leituras de sensor de forma que estados inválidos nem compilem.

Referências: Reference: padrões · Reference: enums · Book: enums

Resumo em 30 segundos
  • struct agrupa campos (como @dataclass). enum diz que um valor é uma entre várias variantes, e cada variante carrega os próprios dados.
  • match obriga a tratar todas as variantes. Se alguém criar uma variante nova, cada match que não a trata vira erro de compilação.
  • O match do Python 3.10+ é parecido na sintaxe, mas não é exaustivo: um caso esquecido passa calado.

O que é

structs e enums são os tipos que você cria. Enums que carregam dados são chamados de ADT, tipos algébricos. O match compara um valor com padrões e desestrutura os campos.

Para que serve

representar o domínio sem campos opcionais soltos. Uma ordem a mercado não tem preço-limite; uma ordem limitada tem. Com enum, o preço só existe na variante que precisa dele.
Siglas e termos difíceis
ADT
Algebraic Data Type, tipo algébrico de dados. Nome acadêmico para enums com dados.
Variante
cada opção do enum (Mercado, Limitada, StopLimit).
Exaustividade
o match precisa cobrir todos os casos possíveis.
Guarda
condição extra num braço do match: x if x > 10 =>.
derive
atributo que gera implementações prontas (Debug, Clone, PartialEq).

06Parte A · Base da linguagem

Erros: Result, Option e exceções

Como o erro aparece na assinatura em Rust e como ele vira exceção quando atravessa para o Python.

Referências: Reference: operador ? · Book: tratamento de erros · CLI Book: erros

Resumo em 30 segundos
  • Rust não tem exceções. Falha esperada é Result<T, E>; ausência é Option<T>; bug é panic!.
  • O operador ? devolve o erro para quem chamou, como uma exceção que sobe, mas visível no tipo da função.
  • Com PyO3, um Err vira uma exceção Python e um panic vira PanicException. Crie exceções próprias com create_exception!.

O que é

Result<T, E> é um enum com duas variantes, Ok(T) e Err(E). Option<T> tem Some(T) e None. O ? desembrulha o Ok ou retorna o Err convertido pelo trait From.

Para que serve

deixar claro no tipo quais funções podem falhar e obrigar quem chama a decidir. Na ponte com Python, permite traduzir cada tipo de erro Rust para a exceção Python certa.
Siglas e termos difíceis
?
operador de propagação. x? equivale a match x { Ok(v) => v, Err(e) => return Err(e.into()) }.
panic
falha irrecuperável. Encerra a thread. Use para bug, não para entrada inválida.
From
trait de conversão. O ? usa para converter um erro de um tipo em outro.
anyhow
crate para aplicações: qualquer erro, com contexto encadeado.
thiserror
crate para bibliotecas: gera Display e From para seus enums de erro.

07Parte A · Base da linguagem

Traits e generics

Interfaces sem herança: um indicador técnico, vários tipos, o mesmo código.

Referências: Reference: traits · Reference: trait objects · Book: generics e traits

Resumo em 30 segundos
  • Trait é um contrato de métodos, como um Protocol do Python, só que checado na compilação.
  • Generics (fn f<T: Trait>) geram uma versão do código para cada tipo: custo zero. dyn Trait escolhe em execução, como o duck typing do Python.
  • Use generics por padrão; use Box<dyn Trait> quando precisar de uma lista com tipos diferentes.

O que é

um trait declara métodos que um tipo promete ter. Generics são parâmetros de tipo (T) restritos por traits (T: Indicador). O compilador gera uma cópia da função por tipo concreto, processo chamado monomorfização.

Para que serve

escrever código reutilizável sem herança e sem perder desempenho. Um backtest genérico aceita qualquer indicador; um driver de sensor genérico roda em qualquer microcontrolador que implemente o trait de I2C.
Siglas e termos difíceis
Trait bound
restrição sobre o genérico: T: Indicador + Send.
dyn Trait
objeto de trait. Despacho dinâmico via vtable.
vtable
tabela de ponteiros para métodos, usada para descobrir qual função chamar em execução.
Protocol
o equivalente estrutural no Python (typing.Protocol), checado só pelo mypy.
Orphan rule
você só implementa um trait para um tipo se o trait ou o tipo for do seu crate.

Coleções, iteradores e closures

List comprehension, pandas e o pipeline de iteradores que compila para um laço só.

Referências: Book: iteradores e closures · std::iter · std::collections

Resumo em 30 segundos
  • Vec é a list, HashMap é o dict, HashSet é o set, VecDeque é o deque.
  • Iteradores são preguiçosos: filter e map não fazem nada até um consumidor (collect, sum, for) puxar os valores.
  • slice.windows(n) resolve janelas móveis sem índice manual. É a base dos indicadores técnicos.

O que é

closure é uma função anônima que captura variáveis do ambiente (|p| p * taxa). Um iterador é qualquer tipo que implementa Iterator::next. Adaptadores (map, filter, zip) encadeiam; consumidores (sum, collect) executam.

Para que serve

processar coleções de forma declarativa, como pandas e list comprehensions, com o desempenho de um laço escrito à mão. O compilador funde a cadeia inteira em um laço, sem listas intermediárias.
Siglas e termos difíceis
Lazy
preguiçoso. Nada é calculado até ser pedido.
Fn / FnMut / FnOnce
closures que só leem, que alteram ou que consomem o que capturaram.
move
força a closure a tomar posse das variáveis capturadas. Obrigatório para enviar a outra thread.
Big-O
notação de custo. Busca em HashMap é O(1) médio; em Vec é O(n).

09Parte B · Ponte Python ↔ Rust

PyO3 e maturin na prática

Funções, classes com estado e arrays NumPy sem cópia, liberando o GIL durante o cálculo.

Referências: Guia do PyO3 · rust-numpy · Nomicon: FFI

Resumo em 30 segundos
  • #[pyfunction] exporta uma função, #[pyclass] + #[pymethods] exportam uma classe, #[pymodule] monta o módulo.
  • Os tipos convertem sozinhos: list[float] ↔ Vec<f64>, dict ↔ HashMap, None ↔ Option, tupla ↔ tupla.
  • Para arrays grandes, use PyReadonlyArray1<f64> do crate numpy: o Rust lê a memória do NumPy direto, sem copiar. Dentro de py.allow_threads, o GIL fica livre para outras threads Python.

O que é

PyO3 é o crate que liga Rust ao interpretador CPython. Ele gera o código de FFI que o CPython espera de uma extensão nativa. O maturin compila esse crate e empacota como módulo Python.

Para que serve

substituir o trecho lento de um código Python por Rust mantendo a mesma API. É assim que foram feitos Polars, pydantic-core, tokenizers da Hugging Face, orjson e o ruff.
Siglas e termos difíceis
Bound<'py, T>
referência a um objeto Python válida enquanto o GIL está seguro. O 'py é o lifetime do GIL.
PyResult<T>
Result<T, PyErr>. Um Err vira exceção ao voltar para o Python.
extract
conversão de objeto Python para tipo Rust (trait FromPyObject).
pyclass
struct Rust exposta como classe Python. Os dados ficam do lado Rust.
allow_threads
solta o GIL enquanto uma closure Rust roda. Nas versões 0.26+ do PyO3 o nome mudou para detach.
Zero-copy
o Rust lê o buffer do NumPy sem duplicar os dados.
Contíguo
array com elementos vizinhos na memória. Fatias com passo (a[::2]) não são contíguas.

Exemplo 1 — Uma classe com estado: livro de ofertas

O livro de ofertas (order book) guarda as ordens de compra (bids) e de venda (asks) por nível de preço. A exchange manda atualizações; você precisa do melhor preço e do spread a cada mensagem.

O tick precisa ser uma fração exata como 0.01, 0.1 ou 1: guardar escala = 1/tick e dividir o inteiro por ela devolve o preço sem resíduo de ponto flutuante. Por que BTreeMap e não HashMap? Concorrência e async sem GIL

Referências: Book: concorrência · Nomicon: Send e Sync · Tutorial do Tokio

Resumo em 30 segundos
  • No CPython com GIL, threads não aceleram cálculo. Você recorre a multiprocessing, que copia dados entre processos.
  • Em Rust, threads rodam em paralelo de verdade. Os traits Send e Sync garantem na compilação que nada é compartilhado sem proteção.
  • Regra prática: cálculo pesado (CPU-bound) → rayon; muita espera de rede (IO-bound) → tokio.

Estratégia e backtest

A estratégia RSI + Williams %R da monografia em Rust, um simulador para mexer nos parâmetros e os dois erros de método que mais enganam em backtest.

Referências: Monografia: caps. 3.7, 4 e 5 · Documentação do vectorbt · Book: padrões de estado

Resumo em 30 segundos
  • Regra da monografia: compra quando %R ≤ quantil 5% e RSI < quantil 5%; vende quando %R ≥ quantil 95% e RSI ≥ quantil 96%. Uma máquina de estados impede compra em cima de compra.
  • Calcular os quantis com o período inteiro usa dados do futuro (look-ahead). No simulador, troque para "só o passado" e veja o resultado mudar.
  • Com mais de mil operações, taxas decidem tudo. A monografia não informa taxas no texto; refaça com 0,10% por lado antes de confiar no número.

O que é

um backtest simula a estratégia sobre dados históricos, como se ela tivesse operado de verdade, e mede retorno, risco e consistência. O vectorbt faz isso de forma vetorizada em Python; aqui o núcleo é um laço Rust com estado.

Para que serve

descartar estratégias ruins antes de arriscar dinheiro e entender em que mercado uma estratégia funciona. Backtest bem feito não prova que a estratégia vai ganhar; ele mostra quando ela com certeza perderia.

queda do patrimônio em relação ao pico anterior. O máximo é o pior momento do período.

Leitura crítica: dois pontos para checar antes de usar
  1. Os quantis usam o futuro. A seção 3.7 calcula os percentis 5%, 95% e 96% sobre o período inteiro e depois aplica as regras a cada minuto desse mesmo período. Em janeiro, a estratégia usou limites calculados com dados de outubro. Em produção você não teria esses limites. Correção: quantis numa janela passada (expansiva ou móvel), deslocados um passo.
  2. Taxas. O texto não diz se o Portfolio.from_signals recebeu fees; o padrão do vectorbt é zero. A expectativa por operação reportada fica entre 0,01 e 0,09 sobre capital 100. Uma taxa típica de 0,10% por lado custa cerca de 0,20 por ida e volta, mais que a expectativa inteira. Refaça com fees=0.001 e, se possível, com slippage.

Conferido neste caderno

O CRC e a conversão foram compilados com rustc: crc8([0xBE, 0xEF]) dá 0x92, o valor de exemplo do datasheet, e os bytes 0x6666 e 0x8000 viram 25,0 °C e 50,0 %UR.

O teste usa embedded-hal-mock: ele confere, byte a byte, o que o driver enviou ao barramento. Você testa o firmware no PC, no CI, sem placa nenhuma.

Do sensor ao dashboard: MQTT e Python

O gateway Rust publica no MQTT, o Python assina, e o mesmo filtro com histerese roda no firmware e no dashboard.

Referências: Embedded Book: concorrência · rumqttc · paho-mqtt · Mosquitto

Resumo em 30 segundos
  • MQTT é publicar e assinar em tópicos (casa/sala/clima) através de um broker. É leve o suficiente para um ESP32.
  • O alarme não pode ficar ligando e desligando quando a temperatura oscila em cima do limite. Solução: filtro (média exponencial) mais histerese (liga em 28 °C, só desliga em 27 °C).
  • Escreva o filtro uma vez em Rust no_std e exporte com PyO3: firmware e dashboard tomam exatamente a mesma decisão.

O que é

o caminho completo de um dado de IoT. O sensor é lido pelo MCU ou por um gateway, vira uma mensagem JSON publicada num tópico MQTT, o broker distribui para quem assinou, e um serviço Python grava, mostra e alerta.

Para que serve

monitorar ambientes (estufa, servidor caseiro, câmara fria), acionar atuadores e guardar histórico para análise. Rust fica no dispositivo e no gateway, onde memória e confiabilidade importam; Python fica na análise e no painel.
Siglas e termos difíceis
MQTT
Message Queuing Telemetry Transport. Protocolo publicar/assinar sobre TCP.
Broker
servidor que recebe e distribui as mensagens (Mosquitto, EMQX).
Tópico
endereço hierárquico. + casa um nível (casa/+/clima); # casa o resto (casa/#).
QoS
Quality of Service. 0 = no máximo uma vez; 1 = pelo menos uma vez; 2 = exatamente uma vez.
Retain
o broker guarda a última mensagem do tópico e entrega a quem assinar depois.
LWT
Last Will and Testament. Mensagem que o broker publica se o dispositivo cair sem avisar.
EMA
Exponential Moving Average. Filtro: novo = anterior + alfa × (leitura − anterior).
Histerese
limites diferentes para ligar e desligar, para evitar oscilação.
TLS
Transport Layer Security. Criptografia da conexão (porta 8883 no MQTT).

18Parte E · Avançado

Unsafe e o Rustonomicon

O que o unsafe libera, o que continua proibido e como passar memória com segurança entre Rust e Python.

Referências: Nomicon: o que o unsafe faz · Nomicon: FFI · Reference: unsafety · Reference: comportamento indefinido

Resumo em 30 segundos
  • unsafe não desliga o borrow checker. Ele libera cinco operações que o compilador não consegue verificar, e passa para você a obrigação de provar que estão corretas.
  • Todo bloco unsafe leva um comentário // SAFETY: dizendo por que é seguro. Toda função unsafe documenta seu contrato em # Safety.
  • Teste código unsafe com o Miri, que detecta comportamento indefinido que os testes normais não pegam.

O que é

o subconjunto da linguagem em que o programador assume garantias que o compilador não prova. O Nomicon é o livro que explica as regras desse território: aliasing, layout de memória, variância, FFI, Send e Sync.

Para que serve

falar com C e com o Python via ctypes, acessar registradores de hardware, implementar estruturas de dados de baixo nível e, raramente, ganhar desempenho evitando checagens. A boa prática é isolar o unsafe numa função pequena e expor uma API segura por cima.
Siglas e termos difíceis
UB
Undefined Behavior, comportamento indefinido. O compilador pode supor que nunca acontece, então o programa pode fazer qualquer coisa.
Ponteiro cru
*const T e *mut T. Como ponteiros de C: podem ser nulos, soltos ou desalinhados.
Soundness
uma API é sound se nenhum código seguro consegue causar UB através dela.
Miri
interpretador do Rust que executa os testes checando UB. Roda no nightly.
Stacked / Tree Borrows
modelos de aliasing que o Miri usa para decidir se dois ponteiros podem coexistir.
repr(C)
layout de struct igual ao de C, necessário para passar structs por FFI.
ManuallyDrop
impede que o Rust libere um valor ao sair de escopo.

Os cinco superpoderes

Operação liberada Exemplo Risco que você assume
Desreferenciar ponteiro cru *ptr Ponteiro nulo, solto ou desalinhado
Chamar função unsafe ou externa strlen(p), slice::from_raw_parts Cumprir o contrato documentado
Acessar ou alterar static mut static mut CONTADOR Corrida de dados entre threads
Implementar trait unsafe unsafe impl Send for Handle Afirmar que o tipo é seguro entre threads
Ler campo de union u.f Interpretar bytes com o tipo errado

Exemplo 1 — Comportamento indefinido que compila e o Miri pega

Sem o unsafe, o primeiro programa nem compilaria: o borrow checker recusaria dois &mut. Com ponteiro cru, ele compila e o erro só aparece no Miri. É por isso que unsafe pede revisão redobrada.

Exemplo 2 — Quem libera a memória? Rust aloca, Python usa, Rust libera

A regra de ouro do FFI no Nomicon: memória volta para o alocador que a criou. Se o Rust alocou, o Rust libera.

Conferido neste caderno

As funções volatilidade (capítulo 10) e retornos_criar/serie_liberar foram compiladas como cdylib com rustc (edição 2024) e chamadas pelo ctypes do Python, com os resultados batendo com o NumPy.

O .copy() é obrigatório: sem ele, o array NumPy apontaria para memória que o serie_liberar acabou de devolver. O PyO3 evita toda essa cerimônia porque converte e gerencia a posse por você; use ctypes só quando a biblioteca precisa servir a outras linguagens.

Checklist de revisão para código unsafe

  • [ ] Cada bloco unsafe tem // SAFETY: explicando qual contrato garante a operação.
  • [ ] Ponteiros vindos de fora são testados contra nulo antes do uso.
  • [ ] Memória é liberada pelo mesmo alocador que a criou.
  • [ ] Nenhuma referência &mut coexiste com outra referência ao mesmo dado.
  • [ ] unsafe impl Send/Sync tem justificativa escrita.
  • [ ] Os testes rodam sob cargo +nightly miri test.

Nightly e o Unstable Book

Como funcionalidades novas chegam à linguagem, quando vale usar o compilador nightly e quando não vale.

Referências: The Unstable Book · rustup: canais · std::simd (nightly)

Resumo em 30 segundos
  • O Rust sai em três canais: stable a cada 6 semanas, beta (o próximo stable) e nightly (todo dia, com funcionalidades em teste).
  • Funcionalidade instável exige #![feature(nome)] no topo do crate e só compila no nightly. O Unstable Book lista todas.
  • Use nightly para ferramentas (Miri, fuzzing, flags -Z) e para experimentar. Biblioteca publicada e serviço em produção ficam no stable.

O que é

o nightly é o compilador construído todo dia a partir do repositório principal. Ele aceita feature gates, interruptores que liberam funcionalidades ainda não estabilizadas. O Unstable Book documenta cada uma, com link para a discussão (RFC) e para a issue de acompanhamento.

Para que serve

usar hoje algo que ainda não chegou ao stable (como SIMD portável) e rodar ferramentas que dependem de partes internas do compilador. O custo é que a API pode mudar ou sumir de uma versão para a outra.
Siglas e termos difíceis
Feature gate
#![feature(...)], chave que habilita uma funcionalidade instável.
RFC
Request for Comments. Proposta formal de mudança na linguagem.
Tracking issue
issue no GitHub que acompanha a estabilização de uma funcionalidade.
SIMD
Single Instruction, Multiple Data. Uma instrução opera em vários números de uma vez.
MSRV
Minimum Supported Rust Version, a versão mínima do compilador que seu crate suporta.
-Z
prefixo de flags instáveis do compilador e do cargo (-Zbuild-std).
from future
o equivalente em Python a um feature gate: liberar hoje uma mudança de uma versão futura.

Exemplo 1 — SIMD portável: somar retornos quatro de cada vez

A soma em blocos muda a ordem das operações, então o resultado pode diferir do laço simples na última casa decimal. Com ponto flutuante, "mais rápido" e "bit a bit igual" nem sempre andam juntos.

Exemplo 2 — Fixar o nightly do projeto e rodar o Miri no CI

Quando uma funcionalidade estabiliza, o #![feature] vira aviso de "feature já estável" e pode ser removido. Fixar a data do nightly evita que uma mudança de API quebre seu build num dia qualquer.

Testes, benchmarks e CI para projetos mistos

Testes unitários e de documentação, testes por propriedade nos dois lados e benchmarks que dizem a verdade.

Referências: Book: testes · proptest · Criterion · Hypothesis

Resumo em 30 segundos
  • cargo test roda três tipos de teste: unitários (#[cfg(test)] no mesmo arquivo), de integração (pasta tests/) e os exemplos da documentação.
  • Teste por propriedade gera centenas de entradas aleatórias e verifica uma regra que vale sempre ("o RSI fica entre 0 e 100"). proptest no Rust, hypothesis no Python.
  • Benchmark sem --release e sem black_box mede o compilador apagando seu código, não seu código.

O que é

o conjunto de ferramentas para provar que o código faz o que deve. Num projeto misto, há testes do lado Rust (rápidos, sem Python) e do lado Python (pela API que o usuário vai chamar), mais um teste de paridade comparando as duas implementações.

Para que serve

refatorar o núcleo Rust sem medo, pegar diferenças sutis entre Rust e pandas (como o tratamento de NaN) e medir se a reescrita realmente ficou mais rápida.
Siglas e termos difíceis
Doc test
exemplo dentro de /// que o cargo test compila e executa.
Property-based testing
testar uma propriedade sobre muitas entradas geradas, em vez de casos escritos à mão.
Shrinking
quando acha uma falha, a ferramenta reduz a entrada ao menor exemplo que ainda falha.
black_box
impede o compilador de otimizar o cálculo do benchmark a ponto de eliminá-lo.
Cobertura
fração das linhas executadas pelos testes (cargo llvm-cov, pytest-cov).
