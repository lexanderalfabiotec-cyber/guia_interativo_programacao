Introdução: o que é Rust

Uma linguagem compilada, o primeiro executável e um mapa para estudar sem se perder.

Referências: Material-base: Guia Completo de Rust · The Rust Programming Language · The Rust Programming Language · The Rust Reference · Guia do PyO3

Resumo em 30 segundos
  • Rust verifica tipos e empréstimos antes de gerar o executável.
  • rustc compila; rustup gerencia a toolchain; Cargo organiza o projeto.
  • Edição da linguagem e versão do compilador são coisas diferentes.

Pense no compilador como aquele colega que revisa tudo antes da entrega. Ele é exigente, mas pelo menos não marca reunião às 18h.

O que é

Rust é uma linguagem de programação compilada, de tipagem estática, voltada a desempenho e segurança. Nasceu como projeto pessoal de Graydon Hoare em 2006, foi adotada pela Mozilla e chegou à versão 1.0 em 2015. Hoje é mantida pela Rust Foundation.

Para que serve

escrever programas tão rápidos quanto C e C++, mas sem os erros clássicos de memória (ponteiro solto, uso depois de liberar, condição de corrida). Ela faz isso sem GC: as regras de ownership são checadas na compilação, então não há pausa de coleta de lixo em execução.

Como usar esta primeira parte

Onde Rust aparece no mundo real:

  • Ferramentas de Python e dados: ruff (linter), uv (gerenciador de pacotes), Polars (DataFrames) e os tokenizers da Hugging Face são escritos em Rust.
  • Infraestrutura: Cloudflare e AWS (Firecracker, a base do Lambda) usam Rust em serviços críticos.
  • Sistemas operacionais: o kernel Linux aceita drivers em Rust desde a versão 6.1.
  • Web e WASM: backends com Axum/Actix e código que roda no navegador via WebAssembly.

O que é

Rust é uma linguagem compilada, com tipagem estática e sem coletor de lixo. A memória é gerenciada por regras de ownership checadas na compilação, então o binário final não tem pausas de GC e não tem a classe de bugs de memória comum em C e C++.

Para que serve

escrever código rápido e seguro onde Python sofre: laços numéricos pesados, serviços com muitas conexões, parsers, ferramentas de linha de comando e firmware. Junto com Python, serve para acelerar só a parte crítica sem reescrever o sistema inteiro.
Siglas e termos difíceis

Garbage Collector, coletor de lixo. Libera memória em tempo de execução. Python usa contagem de referências mais um coletor de ciclos; Rust não tem nenhum dos dois.
GIL
Global Interpreter Lock. Trava do CPython que deixa só uma thread executar bytecode Python por vez.
FFI
Foreign Function Interface. Mecanismo para uma linguagem chamar funções de outra.
ABI
Application Binary Interface. O "contrato binário" de como funções são chamadas na máquina (registradores, pilha, nomes).
Caminho quente
hot path, o trecho do programa onde a maior parte do tempo é gasta.
Crate
unidade de compilação do Rust: uma biblioteca ou um executável. Equivale a um pacote.

Variáveis, mutabilidade, constantes e shadowing

let, mut, const e static: descubra quem pode mudar e quem só trocou de crachá.

Referências: Material-base: Guia Completo de Rust · The Rust Programming Language

Resumo em 30 segundos
  • let cria uma ligação imutável por padrão; mut permite atribuir outro valor.
  • Shadowing declara outra variável e pode trocar o tipo.
  • const exige tipo e valor constante; static representa um local de armazenamento.

Shadowing é trocar o ator mantendo o nome do personagem. mut é o mesmo ator mudando de roupa. O compilador confere os dois elencos.

O que é

em Rust, let cria uma variável imutável por padrão. Para poder alterar, você declara com let mut. Constantes (const) têm valor avaliado em compilação. Uma static define um local de armazenamento com duração do programa; a mutabilidade interior pode permitir alterações controladas. Shadowing é declarar de novo uma variável com o mesmo nome.

Para que serve

a imutabilidade padrão evita alterações acidentais e deixa claro, só lendo a declaração, quais valores mudam ao longo do código. Isso é ainda mais importante com várias threads.

Tipos de dados

Inteiros, floats, tuplas e arrays: escolha uma caixa em que o valor caiba.

Referências: Material-base: Guia Completo de Rust · The Rust Programming Language · Reference: tipos · Book: conceitos comuns

Resumo em 30 segundos
  • Inteiros têm faixa fixa; usize aparece em índices e tamanhos.
  • char é um valor escalar Unicode; String contém texto UTF-8.
  • checked, saturating e wrapping tornam explícita a política de overflow.

Um u8 guarda até 255. Pedir 256 é tentar levar a mudança inteira numa mochila: o problema não é falta de otimismo, é espaço.

O que é

todo valor em Rust tem um tipo conhecido na compilação. Os escalares guardam um único valor (inteiro, decimal, booleano, caractere). Os compostos agrupam vários valores (tupla e array).

Para que serve

o tipo define quanta memória o valor ocupa e quais operações são permitidas. Escolher bem o tipo evita bugs como estouro de inteiro ou erro de arredondamento com dinheiro.

Siglas e termos difíceis
Signed / unsigned
com sinal (i, aceita negativos) e sem sinal (u, só zero e positivos).
Overflow (estouro)
quando o resultado não cabe no tipo. Por padrão, operações inteiras detectadas em execução entram em panic no perfil dev e dão a volta no release; overflow-checks pode mudar essa política. Overflow conhecido na compilação pode ser rejeitado. Use métodos explícitos quando a regra importar.
IEEE 754
padrão de números de ponto flutuante usado por f32 e f64.
Unicode / scalar value
char guarda qualquer caractere Unicode em 4 bytes, inclusive emoji e acentos.
usize / isize
inteiro do tamanho da palavra da CPU (64 bits em máquinas de 64 bits). É o tipo dos índices.
Casting
conversão explícita com as (x as f64).

Resumo em 30 segundos

  • Inteiros têm tamanho fixo (i32, u64...). Não existe o int infinito do Python, então overflow é uma preocupação real.

Ownership (posse) e memória stack/heap

Quem é dono do valor, o que um move transfere e quando os recursos são liberados.

Referências: Material-base: Guia Completo de Rust · The Rust Programming Language · Book: ownership · Nomicon: ownership e lifetimes · Reference: destrutores

Resumo em 30 segundos
  • Um valor tem um dono responsável por sua liberação.
  • Move transfere a posse; Clone duplica explicitamente; Copy permite cópia implícita.
  • Drop libera recursos ao sair de escopo, sem coletor de lixo.

Move é passar a chave da casa; clone é construir outra casa. Se você só quer olhar a sala, peça uma referência: sai bem mais barato.

O que é

ownership é o sistema que Rust usa para gerenciar memória sem GC. Cada valor tem um único dono (a variável que o guarda). Quando o dono sai de escopo, o valor é liberado automaticamente. Atribuir ou passar o valor para outra variável move a posse.

Para que serve

eliminar, já na compilação, três classes de bug que em C/C++ causam falhas de segurança: use after free (usar memória já liberada), double free (liberar duas vezes) e vazamento de memória por esquecimento.

As 3 regras:

  1. Cada valor tem uma variável dona.
  2. Só pode existir um dono por vez.
  3. Quando o dono sai de escopo, o valor é descartado (drop).
Siglas e termos difíceis
Stack (pilha)
memória rápida, organizada em ordem de chegada e saída. Guarda dados de tamanho fixo conhecido na compilação (i32, bool, arrays).
Heap (monte)
memória para dados que crescem ou cujo tamanho só se sabe em execução (String, Vec). Acesso via ponteiro guardado na stack.
Move (mover)
transferir a posse. A variável antiga fica inválida.
Copy
tipos simples da stack (inteiros, bool, char, f64) são copiados bit a bit em vez de movidos.
Clone
cópia profunda explícita, inclusive dos dados na heap (s.clone()). Tem custo.
Drop
função chamada automaticamente quando o valor sai de escopo. É o RAII.
Escopo
trecho delimitado por { } onde a variável existe.

Borrowing, referências e slices

Leia, altere e recorte dados emprestados sem precisar copiar a coleção.

Referências: Material-base: Guia Completo de Rust · The Rust Programming Language

Resumo em 30 segundos
  • Use &T para leitura compartilhada e &mut T para acesso exclusivo.
  • Slices descrevem uma região contínua sem duplicar seus elementos.
  • O empréstimo deve terminar antes de uma alteração incompatível.

Borrowing parece emprestar um livro, só que aqui existe fiscalização para garantir a devolução. Sua biblioteca pessoal gostaria de ter esse compilador.

O que é

borrowing (empréstimo) é usar um valor sem tomar a posse dele, por meio de uma referência. &T é uma referência de leitura (compartilhada); &mut T é uma referência de escrita (exclusiva). Uma slice é uma referência a um pedaço contínuo de uma coleção (&str, &[T]).

Para que serve

permitir que funções leiam ou alterem dados sem copiá-los e sem precisar devolver a posse. O borrow checker garante que nenhuma referência aponte para memória já liberada e que não haja duas escritas simultâneas.

As regras de empréstimo:

  1. Em um dado momento você pode ter muitas referências &T ou uma única &mut T, nunca as duas ao mesmo tempo.
  2. Referências precisam ser sempre válidas: o dado não pode morrer antes da referência.

acessar o valor apontado, com * (*contador += 1).

dois acessos simultâneos à mesma memória, pelo menos um de escrita, sem sincronização. A regra 1 impede isso na compilação.
Dangling reference (referência pendente)
referência para memória já liberada. A regra 2 impede.
NLL (Non-Lexical Lifetimes)
o empréstimo termina no último uso da referência, não no fim do bloco. Isso deixa o compilador menos rígido.
&str vs String
String é dona do texto (heap); &str é uma "janela" emprestada para um texto.

O que é

'static
a referência vale durante todo o programa. Textos literais ("olá") são &'static str, pois ficam gravados no binário.
Dangling
referência para algo que já morreu. É o que os lifetimes impedem.

Smart pointers: Box, Rc, RefCell, Arc

Box, Rc, RefCell e Arc: escolha quem guarda, compartilha e altera o dado.

Referências: Material-base: Guia Completo de Rust · The Rust Programming Language

Resumo em 30 segundos
  • Box oferece posse única de um valor alocado na heap.
  • Rc compartilha posse em uma thread; Arc usa contagem atômica.
  • RefCell checa empréstimos em execução; Mutex coordena acesso entre threads.

Rc divide a conta entre amigos da mesma mesa; Arc aceita gente de outras threads. RefCell confere a comanda na saída: abuso de empréstimo vira panic.

O que é

smart pointers (ponteiros inteligentes) são structs que se comportam como referências, mas são donas do dado e trazem regras extras: guardar na heap, permitir vários donos, ou permitir mutação checada em execução.

Para que serve

resolver os casos em que as regras básicas de ownership não bastam: tipos recursivos (árvores), dados com vários donos (grafos, caches compartilhados) e dados compartilhados entre threads.

Siglas e termos difíceis
Box<T>
coloca T na heap, com um único dono. Custo mínimo.
Rc<T> (Reference Counted)
vários donos na mesma thread. Conta quantos donos existem; libera quando chega a zero.
Arc<T> (Atomic Reference Counted)
como Rc, mas a contagem usa operações atômicas, seguras entre threads.
Atômica
operação que a CPU executa de forma indivisível, sem que outra thread veja um estado intermediário.
RefCell<T>
permite alterar o conteúdo mesmo com referência imutável (interior mutability, mutabilidade interior). As regras de empréstimo são checadas em execução: violar causa panic.
Mutex<T> (mutual exclusion, exclusão mútua)
protege o dado com uma trava; só uma thread por vez mantém a guarda. Tem mecanismo diferente da checagem de empréstimos de RefCell.
Weak<T>
referência que não conta como dono. Evita ciclos que vazariam memória.
Deref
trait que faz o smart pointer se comportar como referência (*box, chamada de métodos direto).

Deadlock é quando duas threads dizem “depois de você” para sempre. Educação demais também trava o sistema.

O que é

concorrência é lidar com várias tarefas que progridem de forma independente; paralelismo é executar trabalho simultaneamente. Rust usa threads do sistema operacional (std::thread), canais para trocar mensagens entre elas (mpsc) e travas para compartilhar estado (Mutex, RwLock). As traits Send e Sync dizem ao compilador o que pode cruzar a fronteira entre threads.

Para que serve

aproveitar todos os núcleos da CPU em tarefas pesadas (processar imagens, treinar modelos, comprimir arquivos). O lema da linguagem é fearless concurrency (concorrência sem medo): condições de corrida viram erro de compilação.

spawn
cria uma thread. Devolve um JoinHandle.
join
espera a thread terminar e pega o resultado.
mpsc (multiple producer, single consumer)
canal com vários produtores e um consumidor.
Deadlock (impasse)
duas threads esperando, cada uma, a trava da outra. Rust não impede deadlock; mantenha travas curtas e uma ordem consistente de aquisição.
Send
o tipo pode ser movido para outra thread. Sync: o tipo pode ser compartilhado por referência entre threads.
CPU-bound vs IO-bound
limitado por cálculo (use threads) vs limitado por espera de rede/disco (use async, capítulo 19).

Async/await com Tokio

Future, runtime, APIs e cancelamento para aproveitar os períodos de espera.

Referências: Material-base: Guia Completo de Rust · The Rust Programming Language

Resumo em 30 segundos
  • async fn produz um Future; o runtime avança as tarefas que podem progredir.
  • join! aguarda operações concorrentes; select! escolhe um ramo concluído.
  • Evite bloquear a thread do executor; separe trabalho pesado de CPU.

Async é o garçom que anota outra mesa enquanto a pizza assa. Criar mais garçons não faz a pizza assar mais rápido: CPU e espera são problemas diferentes.

O que é

programação assíncrona permite que uma thread atenda milhares de tarefas que passam a maior parte do tempo esperando (rede, banco, disco). Uma async fn devolve um Future, um valor que representa um resultado que ainda vai ficar pronto. .await pausa a tarefa até o Future concluir, liberando a thread para outras tarefas. Rust não traz um executor na std; o mais usado é o Tokio.

Para que serve

servidores web, clientes HTTP, bots, gateways de API, consumidores de fila. Qualquer coisa IO-bound com muitas conexões simultâneas. Para cálculo pesado (CPU-bound), threads ou rayon continuam sendo a escolha.

Siglas e termos difíceis
Future
trait que representa um cálculo assíncrono. É preguiçoso: não faz nada até ser aguardado com .await ou entregue ao executor.
Runtime / executor
o "motor" que agenda e executa os Futures. Tokio usa um pool de threads com work stealing (threads ociosas roubam tarefas das ocupadas).
Task (tarefa)
um Future entregue ao runtime com tokio::spawn. Não é uma thread do sistema operacional: seu custo depende do estado guardado no Future e do runtime.
Poll
o executor pergunta ao Future "já terminou?". A resposta é Ready(valor) ou Pending.
Waker
mecanismo que o Future usa para avisar o executor "agora pode me perguntar de novo".
Event loop / reactor
parte do runtime que monitora sockets e timers (via epoll no Linux, kqueue no macOS, IOCP no Windows) e acorda as tarefas certas.
join! / select!
aguardar vários Futures juntos / ficar com o primeiro que terminar.
HTTP (HyperText Transfer Protocol)
e JSON (JavaScript Object Notation): protocolo e formato usados nos exemplos.

Fluxo passo a passo
Etapa ou decisãoO que acontece
Executor → poll(Future)O runtime consulta uma tarefa pronta para progredir.
Ready(valor)A operação terminou e entrega o resultado.

Macros

Gere código com macro_rules!, derive e macros procedurais.

Referências: Material-base: Guia Completo de Rust · The Rust Programming Language

Resumo em 30 segundos
  • Macros transformam sintaxe durante a compilação.
  • macro_rules! usa padrões e repetições; macros procedurais recebem tokens.
  • Prefira funções quando bastarem e inspecione expansões para entender o resultado.

Uma macro escreve código para você. É excelente, até você gerar um labirinto e perceber que o Minotauro também usa cargo expand.

O que é

macros são código que gera código durante a compilação. Há dois tipos: declarativas (macro_rules!), que funcionam por casamento de padrões sobre a sintaxe, e procedurais, que são programas Rust que recebem e devolvem trechos de código (#[derive(...)], #[tokio::main], sql!(...)). Você reconhece uma macro pelo ! no nome ou pelo #[...].

Para que serve

eliminar código repetitivo que funções não conseguem resolver, como aceitar número variável de argumentos (println!, vec!), gerar implementações de traits automaticamente (derive) ou validar SQL e formatos em tempo de compilação.

Siglas e termos difíceis
Metaprogramação
escrever código que escreve código.
Token
menor unidade da sintaxe (um nome, um número, um +).
TokenStream
sequência de tokens que uma macro procedural recebe e devolve.
Fragment specifier (designador)
tipo de trecho que a macro aceita: $x:expr (expressão), $t:ty (tipo), $i:ident (identificador), $l:literal.
Repetição $( ... ),*
casa zero ou mais itens separados por vírgula (+ para um ou mais).
Higiene
variáveis criadas dentro da macro não colidem com as de quem a usa.
cargo expand
ferramenta que mostra o código depois que as macros são expandidas. Ótima para aprender.
Macro Tipo O que gera
println!, format! Declarativa (embutida) Formatação checada na compilação
vec![1, 2, 3] Declarativa Criação e preenchimento de um Vec
#[derive(Debug)] Procedural (derive) impl Debug for Tipo
#[derive(Serialize)] Procedural (serde) Conversão para JSON, YAML, etc.
#[tokio::main] Procedural (atributo) Cria o runtime e envolve o main
sqlx::query! Procedural (função) Valida o SQL contra o banco real ao compilar

Testes

Testes unitários, mocks, integração e documentação que executa.

Referências: Material-base: Guia Completo de Rust · The Rust Programming Language

Resumo em 30 segundos

  • [test] marca testes; cargo test executa o conjunto.

  • Traits permitem substituir banco e rede por implementações falsas.
  • Testes de integração usam a API pública; doc tests verificam os exemplos.

“Na minha máquina funciona” é uma observação. Um teste reproduzível é uma evidência. O compilador agradece a mudança de gênero literário.

Para reproduzir

Crie uma biblioteca com cargo new loja --lib. O nome loja também é usado nos testes de integração e de documentação. Combine as funções públicas em src/lib.rs; exemplos com módulos tests podem ser testados separadamente ou reunidos em um único módulo.

O que é

Rust traz um framework de testes embutido. Uma função marcada com #[test] vira um teste, e cargo test encontra e executa todos eles em paralelo. Existem três tipos: unitários (no mesmo arquivo do código), de integração (pasta tests/) e doc tests (exemplos dentro da documentação, que também são executados).

Para que serve

garantir que o código faz o que deveria e continua fazendo depois de mudanças. Em Rust, o compilador já pega erros de tipo e memória; os testes cuidam da lógica de negócio.

Siglas e termos difíceis
Asserção
verificação que faz o teste falhar se for falsa: assert!, assert_eq!, assert_ne!.
#[cfg(test)]
compila o módulo só quando rodando testes (não vai para o binário final).
#[should_panic]
o teste passa se o código entrar em panic.
#[ignore]
pula o teste por padrão (testes lentos); rode com cargo test -- --ignored.
TDD (Test-Driven Development)
escrever o teste antes do código.
CI (Continuous Integration, integração contínua)
rodar os testes automaticamente a cada push, por exemplo no GitHub Actions.
Mock
objeto falso que substitui uma dependência externa (banco, API) no teste. Em Rust, geralmente feito com traits.

Unsafe e FFI

Isole contratos de memória e converse com C e Python por uma fronteira explícita.

Referências: Material-base: Guia Completo de Rust · The Rust Programming Language

Resumo em 30 segundos
  • unsafe permite operações específicas, com garantias assumidas por quem escreve.
  • FFI exige respeitar ABI, layout, validade e duração dos dados.
  • Uma API segura deve preservar as invariantes do código unsafe interno.

unsafe é pegar a chave do quadro elétrico: dá acesso, mas não transforma um fio desencapado em carregador de celular.

Versão do exemplo

A extensão Python deste capítulo fixa PyO3 0.23, com allow_threads, e usa edição 2021 no manifesto. Os exemplos de FFI com unsafe extern e #[unsafe(no_mangle)] mostram a edição 2024. Mantenha a versão do código e da documentação alinhadas: paralelismo no PyO3 0.23.

Ative um ambiente virtual antes de maturin develop: python3 -m venv .venv e source .venv/bin/activate no Linux/macOS, ou .venv\Scripts\Activate.ps1 no PowerShell.

O que é

unsafe é um bloco onde você assume para si algumas garantias que o compilador não consegue provar. Ele libera cinco "superpoderes": desreferenciar ponteiros crus, chamar funções unsafe, acessar static mut, implementar traits unsafe e ler campos de union. FFI é a ponte para chamar código C (ou ser chamado por C, Python, Node...).

Para que serve

conversar com o sistema operacional, com bibliotecas em C (OpenSSL, SQLite, CUDA), com hardware em sistemas embarcados, e escrever as estruturas de baixo nível que a própria std usa por baixo (Vec, Mutex). A regra de ouro: isole o unsafe em uma função pequena e exponha uma API segura.

Siglas e termos difíceis
Raw pointer (ponteiro cru)
*const T / *mut T. Como ponteiros de C: podem ser nulos ou inválidos.
unsafe não desliga o borrow checker
só libera os cinco superpoderes. O resto continua checado.
FFI (Foreign Function Interface)
chamada entre linguagens.
ABI (Application Binary Interface)
convenção de chamada em nível de máquina. extern "C" usa a ABI de C, que todas as linguagens entendem.
#[unsafe(no_mangle)]
mantém o nome da função exatamente como escrito no binário, para outra linguagem encontrá-la. (Na edition 2021 escrevia-se #[no_mangle].)
cdylib
tipo de crate que gera uma biblioteca dinâmica (.so, .dll, .dylib) para outras linguagens.
PyO3
crate para escrever módulos Python em Rust. maturin: ferramenta que compila e empacota esses módulos como wheel (pacote instalável via pip).
GIL (Global Interpreter Lock)
trava presente nas builds tradicionais do CPython, que limita a execução paralela de bytecode Python; builds sem GIL têm outras regras. Código Rust pode liberá-la e usar todos os núcleos.

PyO3 e maturin na prática

Funções, classes com estado e arrays NumPy sem cópia, liberando o GIL durante o cálculo.

Referências: Guia do PyO3 · rust-numpy · Nomicon: FFI

Resumo em 30 segundos
  • #[pyfunction] exporta uma função, #[pyclass] + #[pymethods] exportam uma classe, #[pymodule] monta o módulo.
  • Os tipos convertem sozinhos: list[float] ↔ Vec<f64>, dict ↔ HashMap, None ↔ Option, tupla ↔ tupla.
  • Para arrays grandes, use PyReadonlyArray1<f64> do crate numpy: o Rust lê a memória do NumPy direto, sem copiar. Dentro de py.allow_threads, o GIL fica livre para outras threads Python.

O que é

PyO3 é o crate que liga Rust ao interpretador CPython. Ele gera o código de FFI que o CPython espera de uma extensão nativa. O maturin compila esse crate e empacota como módulo Python.

Para que serve

substituir o trecho lento de um código Python por Rust mantendo a mesma API. É assim que foram feitos Polars, pydantic-core, tokenizers da Hugging Face, orjson e o ruff.

PyResult<T>

Concorrência e async sem GIL

Threads de verdade com rayon, async com tokio, e por que o compilador impede corrida de dados.

Referências: Book: concorrência · Nomicon: Send e Sync · Tutorial do Tokio

Resumo em 30 segundos
  • No CPython com GIL, threads não aceleram cálculo. Você recorre a multiprocessing, que copia dados entre processos.
  • Em Rust, threads rodam em paralelo de verdade. Os traits Send e Sync garantem na compilação que nada é compartilhado sem proteção.
  • Regra prática: cálculo pesado (CPU-bound) → rayon; muita espera de rede (IO-bound) → tokio.

Resumo em 30 segundos

  • Teste código unsafe com o Miri, que detecta comportamento indefinido que os testes normais não pegam.

O que é

o subconjunto da linguagem em que o programador assume garantias que o compilador não prova. O Nomicon é o livro que explica as regras desse território: aliasing, layout de memória, variância, FFI, Send e Sync.

Para que serve

falar com C e com o Python via ctypes, acessar registradores de hardware, implementar estruturas de dados de baixo nível e, raramente, ganhar desempenho evitando checagens. A boa prática é isolar o unsafe numa função pequena e expor uma API segura por cima.
Siglas e termos difíceis
UB
Undefined Behavior, comportamento indefinido. O compilador pode supor que nunca acontece, então o programa pode fazer qualquer coisa.
Ponteiro cru
*const T e *mut T. Como ponteiros de C: podem ser nulos, soltos ou desalinhados.
Soundness
uma API é sound se nenhum código seguro consegue causar UB através dela.
Miri
interpretador do Rust que executa os testes checando UB. Roda no nightly.
Stacked / Tree Borrows
modelos de aliasing que o Miri usa para decidir se dois ponteiros podem coexistir.
repr(C)
layout de struct igual ao de C, necessário para passar structs por FFI.
ManuallyDrop
impede que o Rust libere um valor ao sair de escopo.

Checklist de revisão para código unsafe

  • [ ] Cada bloco unsafe tem // SAFETY: explicando qual contrato garante a operação.
  • [ ] Ponteiros vindos de fora são testados contra nulo antes do uso.
  • [ ] Memória é liberada pelo mesmo alocador que a criou.
  • [ ] Nenhuma referência &mut coexiste com outra referência ao mesmo dado.
  • [ ] unsafe impl Send/Sync tem justificativa escrita.
  • [ ] Os testes rodam sob cargo +nightly miri test.

Nightly e o Unstable Book

Como funcionalidades novas chegam à linguagem, quando vale usar o compilador nightly e quando não vale.

Referências: The Unstable Book · rustup: canais · std::simd (nightly)

Resumo em 30 segundos
  • O Rust sai em três canais: stable a cada 6 semanas, beta (o próximo stable) e nightly (todo dia, com funcionalidades em teste).
  • Funcionalidade instável exige #![feature(nome)] no topo do crate e só compila no nightly. O Unstable Book lista todas.
  • Use nightly para ferramentas (Miri, fuzzing, flags -Z) e para experimentar. Biblioteca publicada e serviço em produção ficam no stable.

O que é

o nightly é o compilador construído todo dia a partir do repositório principal. Ele aceita feature gates, interruptores que liberam funcionalidades ainda não estabilizadas. O Unstable Book documenta cada uma, com link para a discussão (RFC) e para a issue de acompanhamento.

Para que serve

usar hoje algo que ainda não chegou ao stable (como SIMD portável) e rodar ferramentas que dependem de partes internas do compilador. O custo é que a API pode mudar ou sumir de uma versão para a outra.
Siglas e termos difíceis
Feature gate
#![feature(...)], chave que habilita uma funcionalidade instável.
RFC
Request for Comments. Proposta formal de mudança na linguagem.
Tracking issue
issue no GitHub que acompanha a estabilização de uma funcionalidade.
SIMD
Single Instruction, Multiple Data. Uma instrução opera em vários números de uma vez.
MSRV
Minimum Supported Rust Version, a versão mínima do compilador que seu crate suporta.
-Z
prefixo de flags instáveis do compilador e do cargo (-Zbuild-std).
from future
o equivalente em Python a um feature gate: liberar hoje uma mudança de uma versão futura.

Exemplo 1 — SIMD portável: somar retornos quatro de cada vez

A soma em blocos muda a ordem das operações, então o resultado pode diferir do laço simples na última casa decimal. Com ponto flutuante, "mais rápido" e "bit a bit igual" nem sempre andam juntos.

Exemplo 2 — Fixar o nightly do projeto e rodar o Miri no CI

Quando uma funcionalidade estabiliza, o #![feature] vira aviso de "feature já estável" e pode ser removido. Fixar a data do nightly evita que uma mudança de API quebre seu build num dia qualquer.

Testes, benchmarks e CI para projetos mistos

Testes unitários e de documentação, testes por propriedade nos dois lados e benchmarks que dizem a verdade.

Referências: Book: testes · proptest · Criterion · Hypothesis

Resumo em 30 segundos
  • cargo test roda três tipos de teste: unitários (#[cfg(test)] no mesmo arquivo), de integração (pasta tests/) e os exemplos da documentação.
  • Teste por propriedade gera centenas de entradas aleatórias e verifica uma regra que vale sempre ("o RSI fica entre 0 e 100"). proptest no Rust, hypothesis no Python.
  • Benchmark sem --release e sem black_box mede o compilador apagando seu código, não seu código.

O que é

o conjunto de ferramentas para provar que o código faz o que deve. Num projeto misto, há testes do lado Rust (rápidos, sem Python) e do lado Python (pela API que o usuário vai chamar), mais um teste de paridade comparando as duas implementações.

Para que serve

refatorar o núcleo Rust sem medo, pegar diferenças sutis entre Rust e pandas (como o tratamento de NaN) e medir se a reescrita realmente ficou mais rápida.
Siglas e termos difíceis
Doc test
exemplo dentro de /// que o cargo test compila e executa.
Property-based testing
testar uma propriedade sobre muitas entradas geradas, em vez de casos escritos à mão.
Shrinking
quando acha uma falha, a ferramenta reduz a entrada ao menor exemplo que ainda falha.
black_box
impede o compilador de otimizar o cálculo do benchmark a ponto de eliminá-lo.
Cobertura
fração das linhas executadas pelos testes (cargo llvm-cov, pytest-cov).
