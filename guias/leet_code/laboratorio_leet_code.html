01Parte A · Fundamentos

Método e Big-O

Leia as restrições, estime o custo e só então escreva código.

Referências: Tech Interview Handbook: algoritmos · Competitive Programmer's Handbook, cap. 2

Resumo em 30 segundos
  • Leia as restrições antes de pensar em código: o tamanho de n diz qual complexidade cabe no limite de tempo.
  • Resolva em etapas: entender, exemplos, força bruta, gargalo, padrão, código, teste à mão.
  • Big-O descreve como o custo cresce. O expoente pesa muito mais que as constantes.

O LeetCode não dá nota por esforço. TLE é o jeito educado de dizer que sua solução O(n²) chegou atrasada para uma entrada de 10⁵ elementos.

O que é

Big-O é a notação que descreve como o tempo e a memória crescem quando a entrada cresce, ignorando constantes e termos menores. O(n) dobra quando n dobra; O(n²) quadruplica.

Para que serve

Escolher a abordagem antes de escrever. Se o enunciado diz n ≤ 10⁵, uma solução O(n²) faz 10¹⁰ operações e estoura o tempo. Você descobre isso em dez segundos, sem rodar nada.

Siglas e termos difíceis
n
tamanho da entrada: elementos do array, caracteres da string, nós do grafo.
TLE
Time Limit Exceeded. A resposta pode estar certa, mas demorou demais.
MLE
Memory Limit Exceeded. Usou memória demais.
WA
Wrong Answer. Algum caso de teste deu resultado errado, quase sempre um caso de borda.
Amortizado
custo médio por operação numa sequência longa. O append do Python é O(1) amortizado: às vezes copia tudo, mas raramente.
log n
quantas vezes dá para dividir n por 2 até chegar a 1. Para 10⁹, são cerca de 30 vezes.

O tamanho de n entrega o padrão

Regra de bolso para cerca de 1 segundo numa linguagem compilada, onde cabem perto de 10⁸ operações simples. Em Python, conte com algo entre 10 e 50 vezes menos.

O roteiro em sete passos

A ordem importa: cada passo alimenta o seguinte. Em entrevista, diga cada passo em voz alta.

  1. Entender. Repita o problema com suas palavras. Pergunte: pode ter repetidos? Negativos? Entrada vazia?
  2. Exemplos. Monte dois casos pequenos e um de borda (vazio, um elemento, todos iguais).
  3. Força bruta. Diga a solução óbvia e o custo dela. Ela é o seu plano B e a referência para testar.
  4. Gargalo. Onde a força bruta repete trabalho? Quase sempre é um laço interno que procura algo.
  5. Padrão. Troque o laço interno pela estrutura certa: hash, ponteiros, heap, tabela de DP.
  6. Código. Nomes claros, sem otimizar cedo demais.
  7. Teste à mão. Rode um exemplo linha a linha antes de enviar.
#217

Contains Duplicate

Fácil
Tempo O(n)Espaço O(n)hash setAbrir no LeetCode

Dado um array de inteiros, devolva true se algum valor aparecer pelo menos duas vezes.

Os três primeiros passos do roteiro dão três soluções, cada uma melhor que a anterior:

AbordagemTempoEspaçoIdeia
Força brutaO(n²)O(1)Compara cada par
OrdenarO(n log n)O(1)*Repetidos ficam vizinhos
ConjuntoO(n)O(n)Lembra o que já viu

* A ordenação no lugar não usa memória extra para os dados, mas modifica a entrada, o que nem sempre é permitido.

Nas três linguagens
  • pyx in set é O(1) na média. O mesmo x in list seria O(n) e transformaria tudo em O(n²).
  • rsHashSet::insert devolve false quando o valor já estava lá, então busca e inserção viram uma operação só.
  • goGo não tem tipo set. O idioma é map[T]struct{}, porque struct{} ocupa zero bytes.
No mundo real
  • Idempotência de pagamentos: antes de processar uma transação, o serviço checa se o ID já foi visto, exatamente este problema.
  • Cadastro: recusar e-mail ou CPF repetido numa importação de planilha.
02Parte A · Fundamentos

O kit das três linguagens

Hash map, conjunto, pilha, fila e heap em Python, Rust e Go, lado a lado.

Referências: Python: collections · Rust: std::collections · Go: pacote slices

Resumo em 30 segundos
  • Em entrevista, escolher a estrutura certa vale mais que decorar sintaxe, mas travar na sintaxe custa minutos preciosos.
  • Python traz tudo pronto (Counter, deque, heapq). Rust tem tipos ricos e cobra overflow e empréstimos. Go é explícito: fila é slice, heap é interface.
  • Assinaturas do LeetCode: Python usa class Solution, Rust usa funções associadas em impl Solution, Go usa funções soltas.

Saber três linguagens em entrevista é como saber três idiomas numa viagem: ajuda muito, desde que você não peça o café em Rust e o pão em Go na mesma frase.

O que é

A tabela de equivalências das estruturas que aparecem em quase todo problema: lista dinâmica, hash map, conjunto, pilha, fila e heap.

Para que serve

Traduzir a ideia para código sem parar para procurar documentação, e conhecer as armadilhas de cada linguagem antes que elas virem WA.

As armadilhas que mais custam pontos
  • py[[0] * n] * m cria m referências para a mesma linha. Use [[0] * n for _ in range(m)].
  • pyRecursão passa de 1000 níveis e dá RecursionError. Prefira BFS ou pilha explícita em grafos grandes.
  • rsOverflow de i32 causa panic em modo debug e dá a volta em release. Não conte com nenhum dos dois: use i64 quando a soma puder passar de 2³¹.
  • rsr -= 1 com r: usize igual a 0 também é overflow. Teste o limite antes de subtrair.
  • gofor i, c := range s anda por runes, e i é o índice em bytes. Para texto ASCII, s[i] com laço de índice é mais simples.
  • goSlices compartilham o array por baixo. Guardar atual no resultado sem copiar faz o resultado mudar depois (capítulo 13).

Como o LeetCode chama seu código

Em Python, o juiz instancia Solution() e chama o método. Em Rust, chama Solution::nome(args); a struct vazia Solution já existe e você escreve só o impl. Em Go, chama a função diretamente, e os pacotes padrão mais usados já vêm importados: por isso as abas Go mostram os imports no título em vez de no código. Para rodar localmente, acrescente package main e os imports indicados.

Os recursos usados aqui (min e max embutidos e o pacote slices) exigem Go 1.21 ou mais novo. Se o juiz reclamar, troque por funções auxiliares de duas linhas.

#242

Valid Anagram

Fácil
Tempo O(n)Espaço O(1)contagemAbrir no LeetCode

Duas strings de letras minúsculas são anagramas se usam exatamente as mesmas letras, nas mesmas quantidades. Diga se s e t são anagramas.

Ideia: com um alfabeto fixo de 26 letras, um vetor de contagem substitui o hash map. Some 1 para cada letra de s, subtraia 1 para cada letra de t; se tudo voltar a zero, são anagramas.

Nas três linguagens
  • pyord(c) - ord("a") converte letra em índice. A versão de uma linha com Counter também é O(n), só com constante maior.
  • rsb'a' é o literal de byte. Subtrair bytes dá u8, e o as usize vira índice.
  • goArrays de tamanho fixo são comparáveis com ==: comparar com [26]int{} checa as 26 posições de uma vez.
No mundo real
  • Conferência de pedidos: o que foi separado no estoque tem os mesmos itens, nas mesmas quantidades, do que foi pedido? Ordem não importa.
  • Detecção de fraude simples: nomes de usuário que são anagramas de marcas conhecidas.
03Parte B · Arrays e strings

Arrays e hashing

Troque memória por tempo: lembre do que já passou.

Referências: NeetCode: Arrays & Hashing

Resumo em 30 segundos
  • Um hash map responde "já vi isso?" em O(1) na média. É a troca clássica de memória por tempo.
  • A pergunta que destrava o problema: "o que eu preciso lembrar do que já passou?"
  • Escolher a chave certa é metade da solução: o complemento no Two Sum, a assinatura de letras no Group Anagrams.

O hash map é o canivete suíço do LeetCode. Às vezes ele não é a melhor ferramenta, mas raramente é uma ferramenta ruim.

O que é

Uma tabela que transforma a chave em posição de memória por uma função de hash. Busca, inserção e remoção custam O(1) na média; no pior caso, com muitas colisões, O(n).

Para que serve

Eliminar o laço interno que procura algo. Onde a força bruta pergunta "existe um j tal que…?", o hash map responde na hora.

#1

Two Sum

Fácil
Tempo O(n)Espaço O(n)hash mapAbrir no LeetCode

Dado um array e um alvo, devolva os índices de dois elementos diferentes cuja soma é o alvo. Existe exatamente uma resposta.

Ideia: para cada x, o par que falta é target − x. Se ele já passou, a resposta é imediata. A ordem "checa, depois grava" impede usar o mesmo elemento duas vezes, como em [3, 3] com alvo 6.

Nas três linguagens
  • pyenumerate entrega índice e valor juntos; in num dict testa a chave.
  • rsget devolve Option<&V>; o if let Some(&j) desembrulha e copia o índice. Os índices são usize e precisam de as i32 na saída.
  • goO "comma ok" (j, ok := m[k]) é essencial: sem ele, chave ausente devolve 0, que também é um índice válido.
#49

Group Anagrams

Médio
Tempo O(n·k)Espaço O(n·k)hash map · chaveAbrir no LeetCode

Agrupe as palavras de uma lista que são anagramas entre si. A ordem dos grupos não importa.

Ideia: anagramas compartilham uma assinatura. Ordenar cada palavra funciona (custo O(k log k) por palavra), mas a contagem das 26 letras é O(k) e serve de chave do mesmo jeito.

Nas três linguagens
  • pyListas não podem ser chave de dict porque são mutáveis; tuple(chave) resolve. defaultdict(list) evita o "se não existe, cria".
  • rsArrays [u8; 26] implementam Hash, então viram chave direto. entry(...).or_default() cria o Vec vazio quando precisa.
  • goArrays também são comparáveis e servem de chave de map. append num slice nil funciona sem inicializar.
No mundo real
  • Conciliação bancária: achar dois lançamentos que somam o valor de um boleto é um Two Sum com centavos.
  • Agrupamento de transações: "PADARIA DO ZE 123" e "PADARIA DO ZE 456" caem no mesmo grupo quando a chave é o nome normalizado.
04Parte B · Arrays e strings

Dois ponteiros

Dois índices que se movem com uma regra e eliminam um laço inteiro.

Referências: NeetCode: Two Pointers

Resumo em 30 segundos
  • Dois índices percorrem a estrutura com uma regra: das pontas para o meio, ou um rápido e um lento.
  • Precisa de alguma ordem (array ordenado) ou simetria (palíndromo) para saber qual ponteiro mover.
  • Transforma o par de laços O(n²) em uma passada O(n). No 3Sum, um laço fixo mais dois ponteiros dá O(n²) em vez de O(n³).

Dois ponteiros são aquele casal que arruma a casa começando cada um por uma ponta: se combinarem a regra, se encontram no meio sem limpar o mesmo cômodo duas vezes.

O que é

A técnica de dois ponteiros mantém dois índices l e r e, a cada passo, move um deles com base numa comparação. Nenhum volta atrás.

Para que serve

Encontrar pares ou trios com uma propriedade, comparar duas sequências ordenadas e remover duplicados no lugar, sem memória extra.

#11

Container With Most Water

Médio
Tempo O(n)Espaço O(1)dois ponteirosAbrir no LeetCode

Cada posição do array é a altura de uma parede. Escolha duas paredes que, com o eixo x, formem o recipiente com mais água. A área é a distância entre elas vezes a menor altura.

Ideia: comece pelas pontas, que dão a maior largura. Ao andar para dentro, a largura só diminui; a única chance de melhorar é encontrar uma parede mais alta. Por isso move-se sempre o lado mais baixo: manter a parede baixa e trocar a alta nunca aumenta a área.

Por que dá para descartar

Se height[l] < height[r], qualquer recipiente que use l com outra parede entre l e r tem largura menor e altura limitada pelo mesmo height[l]. Nenhum supera o atual, então l pode sair do jogo. É esse argumento que transforma um palpite em algoritmo correto.

#15

3Sum

Médio
Tempo O(n²)Espaço O(1) extraordenação · dois ponteirosAbrir no LeetCode

Encontre todos os trios de valores do array que somam zero, sem repetir trios.

Ideia: ordene. Fixe o primeiro número nums[i] e procure os outros dois com dois ponteiros no resto do array: soma pequena, sobe l; soma grande, desce r. Para não repetir trios, pule valores iguais ao anterior tanto no i quanto no l.

Nas três linguagens
  • pynums.sort() ordena no lugar; sorted(nums) criaria uma cópia.
  • rsmut nums no parâmetro: a função é dona do Vec e pode ordená-lo. n.saturating_sub(2) evita underflow de usize com menos de dois elementos.
  • goswitch sem expressão é o if/else if idiomático. sort.Ints e slices.Sort ordenam no lugar.
No mundo real
  • Merge de extratos: juntar dois arquivos ordenados por data numa única passada, como no passo final do merge sort.
  • Casamento de ordens: num livro de ofertas ordenado, um ponteiro nas compras e outro nas vendas avançam conforme os preços se cruzam.
05Parte B · Arrays e strings

Janela deslizante

Subarray ou substring contígua: cresça pela direita, encolha pela esquerda.

Referências: NeetCode: Sliding Window

Resumo em 30 segundos
  • Pista no enunciado: "subarray" ou "substring" contígua com alguma condição (maior, menor, no máximo k distintos).
  • A janela [l, r] cresce pela direita e encolhe pela esquerda quando a condição quebra.
  • Cada índice entra uma vez e sai no máximo uma vez: O(n), mesmo com o laço de encolher dentro do laço principal.

A janela deslizante é a fila do pão: entra gente por trás, sai gente pela frente, e você só precisa contar quem está dentro.

O que é

Uma variação de dois ponteiros em que os dois andam na mesma direção e delimitam um trecho contíguo. Um resumo da janela (soma, contagem, último índice de cada caractere) é atualizado a cada movimento.

Para que serve

Responder perguntas sobre trechos contíguos sem recalcular cada trecho do zero. A força bruta testaria O(n²) janelas.

06Parte B · Arrays e strings

Soma de prefixos

Pague uma passada e responda qualquer intervalo com uma subtração.

Referências: Competitive Programmer's Handbook, cap. 9

Resumo em 30 segundos
  • P[i] guarda a soma dos i primeiros elementos. A soma de qualquer intervalo vira uma subtração.
  • Com um hash map de prefixos já vistos, você conta subarrays com soma k em O(n), inclusive com números negativos.
  • A mesma ideia vale para produtos, XOR e contagens: prefixo e sufixo.

A soma de prefixos é o extrato bancário com saldo acumulado: para saber quanto entrou entre o dia 5 e o dia 20, ninguém soma lançamento por lançamento.

O que é

Um vetor de prefixos pré-calculado em uma passada, com P[0] = 0 e P[i+1] = P[i] + nums[i].

Para que serve

Responder somas de intervalos em O(1) e transformar "existe um subarray com soma k?" em "existe um prefixo anterior igual a P[j] − k?".

A matemática em uma linha

soma(nums[i..j]) = P[j + 1] − P[i] nums = [3, 1, 2, 4] P = [0, 3, 4, 6, 10] soma(nums[1..3]) = P[4] − P[1] = 10 − 3 = 7 (1 + 2 + 4)

Por que a janela deslizante não serve quando há negativos? Porque crescer a janela pode diminuir a soma, e você perde a regra de quando encolher. O prefixo não depende disso.

#560

Subarray Sum Equals K

Médio
Tempo O(n)Espaço O(n)prefixo · hash mapAbrir no LeetCode

Conte quantos subarrays contíguos têm soma igual a k. O array pode ter números negativos.

Ideia: um subarray que termina em j tem soma k quando algum prefixo anterior vale soma − k. Um mapa de "prefixo → quantas vezes" responde isso em O(1). O {0: 1} inicial representa o prefixo vazio, para contar subarrays que começam no índice 0.

Nas três linguagens
  • pydict.get(chave, 0) não cria a chave. Com defaultdict(int), a simples leitura cria entradas inúteis.
  • rsHashMap::from([(0, 1)]) inicializa com um par. .copied().unwrap_or(0) transforma Option<&i32> em número.
  • goLer chave ausente devolve 0, então total += vezes[soma-k] funciona direto. Aqui o valor zero é um aliado.
No mundo real
  • Dashboards: totais por período saem de somas acumuladas pré-calculadas, não de varrer a tabela a cada filtro.
  • Imagens: a "imagem integral" é um prefixo em duas dimensões e permite somar qualquer retângulo em O(1), base de detectores clássicos de rosto.
07Parte B · Arrays e strings

Pilha e pilha monotônica

Pares que se fecham e o próximo elemento maior, em O(n).

Referências: NeetCode: Stack

Resumo em 30 segundos
  • Pilha é LIFO: o último a entrar é o primeiro a sair. Serve para pares que se fecham e para desfazer.
  • Pilha monotônica: mantém os elementos em ordem crescente ou decrescente e responde "próximo maior" ou "próximo menor" para todos em O(n).
  • O(n) mesmo com while dentro do for: cada índice entra e sai da pilha uma única vez.

A pilha é a louça na pia: você sempre lava a de cima. Se tentar puxar o prato do meio, já sabe o que acontece.

O que é

Uma lista em que só o topo é acessado: push empilha, pop desempilha, ambos em O(1). Nas três linguagens é só um vetor dinâmico usado pelo fim.

Para que serve

Validar estruturas aninhadas (parênteses, tags, JSON), simular recursão sem estourar a pilha de chamadas e achar o próximo elemento maior.

#20

Busca binária

Metade do problema some a cada passo, inclusive quando o array é a própria resposta.

Referências: Python: bisect · Go: sort.Search

Resumo em 30 segundos
  • A cada comparação, metade do espaço de busca é descartada: O(log n). Para 10⁹ elementos, cerca de 30 passos.
  • Funciona em qualquer coisa monotônica, não só em arrays ordenados. A busca na resposta procura o menor valor que satisfaz uma condição.
  • Escolha um invariante e não mude no meio: intervalo fechado [lo, hi] ou semiaberto [lo, hi).

A busca binária é o jogo do "pensei num número de 1 a 100": quem chuta 50 primeiro ganha; quem chuta 1, 2, 3… perde a festa.

O que é

Um laço que mantém um intervalo onde a resposta com certeza está, compara o meio e corta o lado errado. Termina quando o intervalo fica vazio ou com um elemento.

Para que serve

Procurar em dados ordenados e, mais importante em entrevista, achar o menor ou maior parâmetro que funciona quando testar um parâmetro é fácil.

A matemática do log

depois de k passos restam n / 2^k elementos n / 2^k = 1 ⇒ k = log₂ n n = 1 000 000 000 ⇒ k ≈ 29,9 ⇒ 30 comparações

Árvores: DFS e BFS

Fundo primeiro com recursão, nível por nível com fila.

Referências: NeetCode: Trees

Resumo em 30 segundos
  • DFS vai fundo antes de ir para o lado: recursão ou pilha. BFS vai nível por nível: fila.
  • A resposta depende de combinar o resultado dos filhos? DFS em pós-ordem. Depende do nível ou da distância? BFS.
  • Em Rust, nós de árvore no LeetCode são Option<Rc<RefCell<TreeNode>>>. Parece assustador; na prática são três palavras: opcional, compartilhado, mutável.

Toda árvore binária de entrevista tem duas perguntas escondidas: "você sabe recursão?" e "você lembra do caso base?". A segunda derruba mais gente.

O que é

Uma árvore binária tem nós com até dois filhos, sem ciclos. A profundidade máxima é a altura h: log n numa árvore equilibrada, n no pior caso.

Para que serve

Representar hierarquias e dados ordenados (BST). Os percursos DFS e BFS resolvem quase todo problema de árvore do LeetCode.

Backtracking

Escolha, explore, desfaça: a árvore de decisões em código.

Referências: NeetCode: Backtracking

Resumo em 30 segundos
  • Backtracking percorre a árvore de decisões: escolhe, explora, desfaz a escolha e tenta a próxima.
  • Gera todas as soluções, então é exponencial. A pista no enunciado: "todas as combinações", "todos os subconjuntos" e n ≤ 20.
  • A poda corta ramos que não podem dar certo. Ordenar a entrada costuma habilitar a poda.

Backtracking é o labirinto resolvido com a mão na parede: entra, bate no fim, volta até a última bifurcação e tenta o outro lado. A diferença é que o computador não reclama do joelho.

O que é

Uma busca em profundidade sobre as escolhas possíveis, com um estado (a lista atual) que é modificado antes da chamada recursiva e restaurado depois.

Para que serve

Listar subconjuntos, permutações e combinações, resolver sudoku e problemas de restrição em que não existe atalho melhor que tentar.

O que é

Para que serve

Por que a recursão ingênua explode

f(n) = f(n − 1) + f(n − 2) f(1) = 1, f(2) = 2 sem memória: cada chamada abre duas → cerca de 1,618ⁿ chamadas n = 45 ⇒ ~2,5 bilhões de chamadas com memória: cada f(i) é calculado uma vez → 45 somas

#322

Coin Change

Médio
Tempo O(valor·moedas)Espaço O(valor)DP 1DAbrir no LeetCode

Dadas moedas de valores diferentes e um valor total, devolva o menor número de moedas que forma o valor, ou −1. Há moedas ilimitadas de cada tipo.

Ideia: dp[v] é o mínimo de moedas para formar v. A última moeda usada foi alguma c, então dp[v] = min(dp[v − c] + 1) sobre todas as moedas que cabem. O "infinito" é valor + 1, porque nenhuma resposta válida usa mais moedas que o próprio valor.

Por que o guloso falha aqui

Com moedas [1, 3, 4] e valor 6, pegar sempre a maior dá 4 + 1 + 1 = três moedas. A resposta é 3 + 3 = duas. Moedas do real (1, 5, 10, 25, 50 centavos) são um sistema em que o guloso acerta, mas o problema não garante isso.

Nas três linguagens
  • pyA versão de cima para baixo cabe em duas linhas com @functools.cache, mas a recursão pode passar do limite em valores grandes; a tabela não tem esse problema.
  • rsTudo em usize para indexar sem conversões no laço; só a resposta volta a i32. No Climbing Stairs, n = 45 ainda cabe em i32 (1 836 311 903).
  • gomake([]int, n) já entrega zeros, então dp[0] = 0 é de graça.
No mundo real
  • Troco e cupons: combinar créditos e cupons de valores diferentes para cobrir um total com o mínimo de itens.
  • Planejamento: escolher lotes de compra que somam uma quantidade com custo mínimo é uma variação direta.

Longest Common Subsequence

Médio
Tempo O(m·n)Espaço O(m·n)DP 2DAbrir no LeetCode

Devolva o tamanho da maior subsequência comum de duas strings. Subsequência mantém a ordem, mas pode pular caracteres: "ace" é subsequência de "abcde".

Ideia: se os últimos caracteres dos prefixos são iguais, eles entram na resposta: diagonal + 1. Se não, um deles fica de fora: o maior entre a célula de cima e a da esquerda.

Tabela da LCS

simulador

Verde: letras iguais, valor veio da diagonal. Ao terminar, o caminho em ameixa reconstrói uma subsequência comum mais longa.

Nas três linguagens
  • py[[0] * (n + 1) for _ in range(m + 1)], nunca [[0] * (n + 1)] * (m + 1).
  • rsvec![vec![0; n + 1]; m + 1] clona o vetor interno para cada linha, então aqui não há o problema do Python. as_bytes() permite indexar a string.
  • goNão existe literal 2D com tamanho dinâmico: cria-se o slice externo e um make por linha.
No mundo real
  • diff: o git diff e comparadores de documentos partem da maior subsequência comum de linhas.
  • Busca de nomes: distância de edição, prima da LCS, encontra "Joao Silva" quando o cadastro diz "João da Silva".

Guloso e intervalos

Decisões locais que nunca precisam ser desfeitas, e como provar isso.

Referências: NeetCode: Greedy e Intervals

Resumo em 30 segundos
  • Guloso: a cada passo, a melhor escolha local, sem voltar atrás. Simples e rápido quando funciona.
  • Só use com um argumento de por que funciona: "trocar a escolha gulosa por outra nunca melhora". Sem isso, é chute.
  • Intervalos: ordene pelo início (juntar) ou pelo fim (escolher o máximo de intervalos sem sobreposição) e faça uma passada.

O algoritmo guloso é aquela pessoa que pega o maior pedaço de bolo primeiro. Às vezes está certa. No Coin Change, ela ficou sem troco.

O que é

Uma estratégia que constrói a solução tomando decisões que parecem ótimas no momento e nunca as desfaz.

Para que serve

Agenda, intervalos, saltos e escolhas em que dá para provar que a decisão local não atrapalha o futuro. Costuma ser O(n) ou O(n log n), com a ordenação.

#56

Merge Intervals

Médio
Tempo O(n log n)Espaço O(n)intervalosAbrir no LeetCode

Junte todos os intervalos que se sobrepõem e devolva os intervalos resultantes.

Ideia: ordenados pelo início, intervalos que se sobrepõem ficam vizinhos. Compare cada um só com o último do resultado: se começa antes do fim dele, estica o fim; senão, abre um novo.

Nas três linguagens
  • pysort(key=lambda iv: iv[0]). Na verdade, listas já se ordenam pelo primeiro elemento, mas a chave deixa a intenção explícita.
  • rsUm match com guarda: Some(ultimo) if iv[0] <= ultimo[1] estica; qualquer outro caso empilha. O empréstimo mutável de last_mut() termina antes do push.
  • goultimo := res[len(res)-1] copia só o cabeçalho do slice; alterar ultimo[1] altera o intervalo dentro de res. Aqui o compartilhamento ajuda; no backtracking, atrapalhava.
No mundo real
  • Agenda: juntar os horários ocupados de várias pessoas para achar uma janela livre é Merge Intervals seguido de "o que sobrou".
  • Redes: consolidar faixas de IP em listas de bloqueio para reduzir o número de regras.

Manipulação de bits

XOR, máscaras e deslocamentos: os mesmos símbolos nas três linguagens, quase.

Referências: Go: math/bits · Rust: u32::count_ones

Resumo em 30 segundos
  • XOR anula pares: a ^ a = 0 e a ^ 0 = a. Encontrar o elemento sem par vira uma passada sem memória.
  • i >> 1 divide por 2; i & 1 é o último bit; i & (i − 1) apaga o 1 mais baixo.
  • Os símbolos são quase os mesmos nas três linguagens. O NOT bit a bit muda: ~x no Python, !x no Rust, ^x no Go.

Existem 10 tipos de pessoa: as que entendem binário e as que não entendem. Este capítulo é para mudar de grupo.

O que é

Operar diretamente nos bits de um inteiro com AND, OR, XOR e deslocamentos. Cada operação custa um ciclo de CPU.

Para que serve

Máscaras de permissão, conjuntos pequenos num inteiro (subconjuntos com n ≤ 20), paridade, contagem de bits e truques de memória O(1).

#136

Single Number

Fácil
Tempo O(n)Espaço O(1)XORAbrir no LeetCode

Todo número aparece duas vezes, menos um. Encontre-o em O(n) e memória O(1).

Ideia: o XOR é comutativo e associativo, então a ordem não importa. Fazendo XOR de tudo, cada par vira 0 e sobra o número sozinho.

4 ^ 1 ^ 2 ^ 1 ^ 2 = 4 ^ (1 ^ 1) ^ (2 ^ 2) = 4 ^ 0 ^ 0 = 4
#338

Counting Bits

Fácil
Tempo O(n)Espaço O(1) extrabits · DPAbrir no LeetCode

Para cada i de 0 até n, devolva quantos bits 1 há na representação binária de i.

Ideia: i >> 1 é i sem o último bit, e esse valor já foi calculado porque é menor que i. Some o último bit (i & 1). É uma DP em que a transição é um deslocamento.

Nas três linguagens
  • pyInteiros têm tamanho ilimitado, então ~x de um positivo é negativo (~6 == -7). Para 32 bits, aplique & 0xFFFFFFFF.
  • rsfold(0, |acc, x| acc ^ x) é o XOR acumulado em uma linha. count_ones() existe em todos os inteiros.
  • goEm Go, & tem a mesma precedência que * e é avaliado antes do +. Os parênteses no código são só para quem lê.
No mundo real
  • Permissões Unix: chmod 755 é a máscara 111 101 101: dono lê, escreve e executa; os outros leem e executam.
  • Feature flags: guardar dezenas de opções liga e desliga num único inteiro, testando com flags & FLAG != 0.

#128

Longest Consecutive Sequence

Médio
Tempo O(n)Espaço O(n)hash setAbrir no LeetCode

Dado um array não ordenado, devolva o tamanho da maior sequência de inteiros consecutivos, em O(n).

  1. Entender. "Os números não precisam estar juntos no array, certo? E repetidos contam uma vez?" Sim e sim.
  2. Exemplo. [100, 4, 200, 1, 3, 2] tem 1, 2, 3, 4: resposta 4.
  3. Força bruta. "Ordenando, a sequência fica contígua e uma passada resolve: O(n log n). O enunciado pede O(n), então preciso evitar a ordenação."
  4. Gargalo. "Para cada número, quero saber em O(1) se o próximo existe: conjunto."
  5. Cuidado. "Se eu contar a partir de todo número, conto a mesma sequência várias vezes e volto a O(n²). Só começo a contar em x quando x − 1 não existe: aí x é o início de uma sequência."
  6. Complexidade. "Cada número é visitado no máximo duas vezes, uma no laço externo e uma dentro de uma contagem. O(n) de tempo e de memória."
Frases para destravar
  • "Vou começar pela força bruta para ter algo correto e depois otimizo."
  • "O gargalo é este laço interno procurando X. Que estrutura responde isso mais rápido?"
  • "Posso assumir que a entrada cabe em memória e que os valores cabem em 32 bits?"
  • "Antes de rodar, vou passar este exemplo pelo código linha por linha."

Uma hora por dia, cinco dias por semana. Resolva em uma linguagem principal e reescreva um problema por dia em outra: é o melhor exercício de fluência.

  3. Semana 3: capítulos 07 e 08. Pilha e busca binária, incluindo busca na resposta.
